# Plan update — 2026-11-12

Living status/plan note for the Jogja CCTV viewer. Updated after each
rescan or infrastructure change; history lives in DISCOVERY_PLAN.md.

- **801 cameras, 20 groups, 157 YouTube lives** (114 playable + 43 no-embed cards)
- Live site: https://arifian0-oss.github.io/jogja-cctv-viewer/
- Repo: `arifian0-oss/jogja-cctv-viewer` (public, GitHub Pages)
- Data: `data/` JSON is the source of truth (`data/groups.json` +

  syncs — refresh jobs only update data.js, so rotations drift them until
  synced.

  Kodim Gunungkidul at Bunderan Kodim's stream (fixed back to
  `QiIkBSYNZMU`): a replacement ID must not already belong to another
  entry, and the entry must match the title with strictly more distinctive

## Done 2026-11-12
- **Data split** — the 801-camera dataset moved out of the single-line
  `assets/js/data.js` into `data/` JSON (`groups.json` + 20 per-source files
  under `data/cameras/`, `sources.json` for the refresh jobs); `data.js` is
  now generated by `npm run data` (`tools/build-data.mjs`, validated,
  deterministic, round-trip proof 801/801 cameras and 20/20 groups, zero
  differences). Camera order is grouped by source now, not chronological
  append. Header/footer counts are filled from the data at boot (no
  hardcoded totals), and the offline-hint list (`DEAD_NOW`) is keyed by
  camera name instead of index. Both refresh jobs (hourly Actions + daily
  VM cron) now edit the JSON and regenerate `data.js`. The 19 same-name
  pairs are the deliberate HLS/YouTube mirrors of one camera; the validator
  accepts them only across groups with different kinds.
